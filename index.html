Inventory Fill Rate Optimization

The Problem

My Solution

  • Built async Safety Net Cron Job for ongoing protection
  • Cron scans for stalled orphaned box blockings

Challenge 02

Real-Time Box Suggestions

The Problem

Pre-generated suggestions were stale by Next day. Pickers arrived at empty shelves, wasted time searching, and manually counted loose items.

My Solution
  • Decoupled picking list generation from box suggestion
  • Box suggestion fires in real-time at the rack
  • Algorithm evaluates live stock — fullest box first
  • Full-box picking eliminates manual counting — picker grabs and moves on
+22%
Box Picking per 1K Units + 15% picker efficiency gain
Challenge 03

Order Starvation (Rack-Level Blocking)

The Problem

Orders acted as runaway processes — continuously pulling fresh suggestions, stealing stock earmarked for other orders. No geographic boundary on inventory claiming.

My Solution
  • Rack-Level Blocking: locks SKU + batch qty to specific rack
  • Ring-fences stock so no other order can claim from that rack
  • Smart Over-Picking: worker picks extra unlocked nearby stock
  • System auto-adjusts all future pick paths accordingly
Zero
Starvation Events + Clear per-order stock separation
Challenge 04

High-Throughput Picklist Engine

The Problem

One DB query per item per order — SQL N+1 problem. Concurrent operators fired thousands of DB requests, causing lock-up. Picklists took minutes instead of seconds.

My Solution
  • Bulk Precomputation: fetch all SKU batch data in single indexed read
  • Compute all picklists in memory, commit in one bulk insert
  • One Kafka topic per warehouse for parallel processing across warehouses
  • Sequential consumer per topic ensures zero conflicts within a warehouse
3x
Throughput Under Peak Load + Zero DB lock contention
